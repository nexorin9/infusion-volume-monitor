# 合成短片：这是什么，不是什么

> 本文说明本项目**用于自动化验收的数据从哪来、边界在哪**。
> 一句话：真实院内输液架短片必须经医院授权采集；本轮自动化回归跑在**程序合成**的
> 短片与**公开数据集**上，**替身不是最终验收边界**。

## 为什么需要替身

「护士拍 10–20 秒短片 → 换算成毫升 → 提示该换液」这条链路要验证，就得先有短片。
而真实的输液架短片有三个绕不开的问题：

1. **采集要授权。** 画面里会有床号牌、输液标签、护士的手与工牌，属于院内场景，
   拿不到授权就不能进仓库，也不能进自动化流水线。
2. **拿不到就是拿不到。** 就算授权，真实短片的袋型、光照、遮挡分布都是**长尾**的：
   很难凑齐「4 个袋型 × 5 个液位 × 6 种拍法」的组合，拿少数样本做不出可复现的
   偏差预算。
3. **真值不可得。** 短片拍完之后没人能同时说出「这袋真实还剩多少毫升」——除非先
   称重，那又回到第 1 条。

所以本轮用两条腿替代：

| 用途 | 替代物 | 性质 |
|------|--------|------|
| 袋型标定与毫升换算回归 | `scripts/synthesize_rack.py` 合成短片（已知真值） | 回归基准 |
| 分割精度（IoU / J&F）对照 | 公开视频分割数据集子集（下载脚本化，见 task 21） | 评测基准 |
| 单元测试边界样例 | `tests/fixtures/` 与 `tests/support/` | 单测夹具 |

**三者都是替身。** 上线前必须在院内真实短片上重跑一遍回归，届时才谈得上验收。

## 合成器产出什么

```bash
python scripts/synthesize_rack.py --out data/synth --bags 3 --frames 24 \
    --variant night --occlude B01:4:12 --drip-chamber
```

```
data/synth/<scene_id>/
├── RGB/frame_%05d.jpg        # 画面帧（可重新打包上传）
├── GT/<bag_seq>/%05d.png     # 该袋在该帧的真实液体区域二值掩膜
├── frames.zip                # 可直接 POST /api/v1/infusion/tracks 的帧包
└── manifest.json             # 真值清单
```

`manifest.json` 逐袋逐帧记录：真实液面高度、真实体积分数、**真实毫升数**、理论
面积比、腔体与液体像素计数、是否被手遮挡。**可逐字节复现**——同一个 `seed` 渲出来
的画面帧与真值掩膜完全一致，所以任何人重跑都能得到同样的结论：

```bash
python scripts/synthesize_rack.py --reproduce data/synth/<scene_id>/manifest.json --out data/repro
```

仓库里随附的样例清单见 [`tests/fixtures/rack-synth-scene/manifest.json`](../tests/fixtures/rack-synth-scene/manifest.json)；
仓库**不提交帧**，只提交清单与种子。

GT 目录沿用 `{scene_id}/{object_id}/{frame_id}.png`——与视频分割评测器读取的 GT 目录
一致，因此合成真值可以直接喂给 IoU / J&F 对照，不必再转一次格式。

## 袋腔几何：为什么不能拿一条直线换算

合成器不是「画个矩形填一半」。袋腔用偏心超椭圆描述，横向半宽剖面
`(1 - |u|^p)^(1/p)`；真实体积分数按未变形腔体的宽度剖面积分给出，而**投影**面积比
另带两个观感修正：

| 修正 | 物理来源 | 是否改变真实体积 |
|------|---------|----------------|
| `perspective` | 相机略低于袋中，袋顶比袋底窄 | 否（纯光学） |
| `bulge` | 软袋充盈后下部被液体顶鼓 | 否（体积变化由袋型标定吸收） |

于是「量到的面积比」与「真实体积分数」之间存在**系统性偏差**，且偏差随袋型与液位
变化。实测（`tests/test_calibration_regression.py`）：

| 袋型 | 液面 5% 时 面积比/体积分数 | 液面 95% 时 |
|------|--------------------------|--------------|
| TYPE-A 500 ml 软袋（圆角方袋） | 1.094 | 1.004 |
| TYPE-B 1000 ml 软袋（长袋） | 1.111 | 1.004 |
| TYPE-C 250 ml 硬瓶（方瓶） | 1.056 | 1.002 |
| TYPE-D 250 ml 软袋（扁袋） | 1.132 | 1.006 |

扁袋软袋在低液位上高估最多（+13%），硬瓶最小（+5.6%）。**这就是标定要走分段线性
带、而不是 `可用容量 × 面积比` 一条直线的物理原因**——留出液位上分段带把误差压到
标签容量的 0.4% 以内，朴素直线则要 0.5%–1.9%，且随袋型不同。

## 拍法变体与各自的容差

| 变体 | 模拟什么 | 实测面积比偏差上限 |
|------|---------|-------------------|
| `fixed` | 固定机位 | 0.02 |
| `handheld` | 手持抖动（平移 + 微旋转，画面与真值同步变换） | 0.025 |
| `highlight` | 镜面反光高光（靠孔洞填充吸收） | 0.025 |
| `deform` | 袋体逐帧摆动与鼓缩（真值掩膜同步变形，仍精确） | 0.03 |
| `night` | 夜间暗光（偏蓝衰减 + 噪声） | 0.025 |
| `hand_occlusion` | 手与管路遮挡 | 不设容差——被挡是真值，见下 |

## 三个已量出来的边界结论

回归跑完不是「绿灯就完事」，有几条结论已经改变了主路径的设计：

**1. 袋体几乎排空时，系统报「未观测到」，不报 0 毫升。**
液面 0.5% 时液体区域只剩 850 px，几何核按看不见处理，`fill_ratio` 为空，
门禁走 `no_observation`。0 会被护士读成「袋空了、可以拔管」，而真相是这一帧根本没
看清——这是两种完全不同的含义。液面 2% 起测量恢复正常（偏差 < 0.0005）。

**2. 空滴斗接在袋口时，起锚方式决定会不会读少。**
滴斗与袋体连成同一块前景。用**挂点竖列先验**起锚时，腔体估计把滴斗算进去
（135843 → 142260 px），面积比被压低约 3.3 个百分点，折合 **约 15 ml**。用首帧
枚举出的**袋体候选框**起锚时，滴斗落在框外，两种配置测得的面积比一致。

→ 主路径必须走候选框起锚。竖列先验只作为枚举不可用时的兜底，且此时读数要标降级。

**3. 袋上贴的输液标签会在液面上打出小孔洞。**
标签约 1200 px²，在几何核的 `max_hole_area`（2048 px²）之内，被孔洞填充吸收，
不会在曲线上打出假凹陷。贴更大的标签就另说——那是 task 14 的边界。

## 脱敏纪律

合成器不接受任何来自真实业务的输入，产出里的一切标识都是占位：

| 字段 | 取值 |
|------|------|
| `rack_id` / `bed_no` / `infusion_order_no` | 不由合成器产生（入站必填，由调用方给） |
| `captured_at` | `<EXAMPLE_CAPTURED_AT>` |
| `bag_seq` | `B01`…`B06`（挂位序号，不是任何业务单号） |
| `bag_type_code` | `TYPE-A`…`TYPE-D`（泛化外形代号，不含厂商/批号/效期） |

zip 成员时间戳用固定基准时刻 `2020-01-01`，只为保证可复现，不代表任何拍摄时间。
`tests/test_calibration_regression.py` 里有回归用例盯着这条纪律：清单里一旦出现
长数字、类批号、具体日期或常见住院号前缀，测试即失败。

## 换成真实短片时怎么办

拿到院内授权短片后，回归的口径不需要改，只需换数据源：

1. 按同样的目录约定落 `{video_id}/{bag_seq}/{frame_id}.png` 掩膜（护士称重得到的
   真实毫升写进 manifest 的 `truth`）；
2. 跑同一批 `CALIBRATION_LEVELS` / `HOLDOUT_LEVELS` 对应的液位——真数据里没有
   「指定液位」，改为按标签刻度带对应到最近的液位；
3. 同一组断言重跑。**预算应当放宽**：合成短片没有镜头畸变、没有袋体被手抓变形、
   没有焦点模糊，真实短片的分割误差一定更大。若真数据上的误差落在同一预算内，
   说明合成回归给的是可信的下界；若超出，据实放宽并记录，而不是回头调合成器。
