## 关键不变量（全表）

### 关键不变量

- **点名宁少勿多，三道闸都可解释**：双条件（连续 N 帧 + 余量 margin）之上再加滞回带、每袋最小间隔（15 分钟）、每轮上限（3 袋）。判定按**整轮**做而不是逐袋各判各的——上限与 ETA 排序只有「这一架所有袋子一起看」才成立；被截断与被抑制的袋都带原因码与人话说明，不点名也是一条留痕的结论。滞回与锁定挡的是「反复点名同一袋」，最小间隔挡的是「重启后从头再点一遍」，两者分工不同、都不可省。
- **幂等键**：出站事件以 `client_event_id` 唯一约束；键只由 (会话, 袋序) 决定，**不含确认时刻**——带时间戳的键每次重试都不同，那不叫幂等键。重复确认返回 `{"idempotent_hit": true}` 且事件表不新增行。**规则由服务端唯一持有**：点名清单把键随确认入参一起发下去让终端原样回填，终端自编或改格式一律 422 拒收（而不是按调用方的键入账）。
- **并发/重放防护**：同会话的 transition 串行化（写库事务取写锁后在锁内复核前提，输的那一路回到读路径重判）；同 `rack_id + shift + bag_seq` 重复上传覆盖会话而非追加，短的一段重传会把长的一段留下的帧清掉，不留「本轮不存在的旧帧」。
- **越权写入拒绝**：换液确认必须点名袋序，袋序/输液架与会话不符直接 `403` + 一行 `rejected` 审计——不兼容、不降级、不替人猜。所有拒绝判定都发生在写事务之外，否则回滚会连审计行一起抹掉，恰好抹掉最该留痕的那次尝试。
- **状态校验**：`replaced` 只能由护士确认触发，非法迁移返回 409 并记审计；模型绝不推进状态。
- **模型只有一个入口、降级有据可查**：业务层只经单一网关调模型（换端点只改环境变量，不动业务代码）；四类失败——连接失败 / 连接超时 / 读超时 / 5xx / 输出不可解析——各有独立原因码，处置统一（退避重试 ≤2 次后退确定性阈值路径）。输出不合契约（缺 `trigger_reason`、枚举越界、多出字段、自评置信度低于门禁）一律**不采信**：模型说「我只有 45% 把握」不该被当结论用。模型输出 `replaced` 会被契约拒收——换液确认是护士的动作，模型没有这个权力。
- **模型不能悄悄烧钱、也不能悄悄变慢**：调用数、token 用量、延迟**分位**（均值会被一串快请求压住，端点从 200ms 变 4s 时只有 p95 跟得上涨）、失败率都按 `request_id` 与模型名聚合并进运行摘要；延迟窗口与请求明细桶都有上限（默认 1024 / 256，LRU），病区这台机器还要跑视觉。每日调用上限与单请求 token 上限越过时**一次 HTTP 都不发**，落 `quota_exceeded` 退阈值路径——**护栏只挡不改写**：不做静默截断（截断会让审计记的 `max_tokens` 与端点实际收到的不是一回事），也不拿护栏当下限（被挡下的那次不占当天额度、没调模型的那轮不计入调用数）。额度按**院内工作日 UTC+8** 切，UTC 的日界落在病区凌晨两点而不是交班前。
- **换实现不改出数，缺权重也不静默退回**：业务层只经 `build_predictor()` 取预测器，几何核与生产权重共用同一协议、同一入口，换实现只改 `MODEL_IMPL` / `MODEL_ID` 两个环境变量。选权重档却没权重时服务**起不来**并点名缺哪个变量——悄悄退回几何核看着「还能用」，但同一个 `MODEL_ID` 在两台机上会给出不同的毫升数与 ETA，护士长比对两次巡视记录才发现，这条路走错根本查不出来。
- **毫升数不虚报，证据不足就不修正**：袋型登记了腔体参数时，毫升数由投影面积反解回真实高度再积分得到，低液位的残留（袋壁挂液 + 自校准残差）显式扣除、扣到只剩残留量级时报 `0` 而不是编一个几毫升出来。自校准只用护士确认过的"这袋输完了"当证据，**不足 3 条或彼此打架就不生效**——宁可继续给偏大的数，也不拿两条样本当结论去改全院读数。
- **同一袋型同时只有一个生效版本，改大了也不静默覆盖**：标定带 `effective_from`/`effective_to` 的半开生效区间，登记时即校验相交并拒收（409），改版交接把旧版收口到新区间起点；预约登记（未来生效）当天一个读数都不动，到点才转正。改版后同一袋的新旧读数相对差超 `CALIBRATION_REVIEW_DEVIATION`（默认 15%）时**不覆盖**：旧读数留着、会话挂待复核、告警落 append-only 表，等护理部结案才生效——把一个错的标定直接推到全院读数上，代价比晚几天修正大得多。
- **毫升数要可信才敢拿去点名换液**：每个读数配一条 95% 区间与置信度，由三条证据合成——腔体几何版本（分段带模式用拟合残差）、面积比方差（对降幅去趋势后的残差，不是整段标准差；整段标准差量到的是「漏了多少」）、遮挡帧占比。相对不确定度超 0.14（`1 − 0.60 × 0.35` 的组合门限）即 `low_confidence`，遮挡占比 ≥ 35% 即 `high_occlusion`，两种情况下 `estimated_volume_ml` 与 `eta_minutes` **都不出现**——毫升不可信时由它推出来的时点同样不可信。区间与成因仍照给：护士端要能显示「大概还剩多少、为什么这次没有准数、下一步该做什么」。门禁与 `uncalibrated` 分开报：前者重拍就好，后者要补标定登记。
- **几何参数改了必须升版本**：腔体换算的毫升数带模型误差，登记时分配 `geometry_revision`（首次登记即第 1 版）；历史记录里没有这个键的老数据按「版本缺失」读，历史读数会被门禁挡下并提示补登记，而不是继续给一个「参数可能已经改过、自己却不知道」的数字。改版重算复用同一套门限（观测证据从会话行复原，不因改版凭空放宽区间）。
- **失败不静默改数据**：出站失败进重试队列保持 `pending_writeback`；帧质量差只标 `degraded` 并给补拍建议，不静默改数、不粗暴拒收。
- **清理只清像素，不清读数，更不清留档**：保留期到了清的是输液架的原始帧，**面积比曲线、毫升数、ETA、换液结论全部留在会话行里**——护士长复盘「上周三那袋还剩多少」看的是读数，不是那堆 jpg。没结束的会话（`monitoring`/`needs_change`）、换液事件还没送达对端的、待写回队列里还挂着欠账的，一个都不动；同一段短片的几只袋子共用一个帧目录，只要有一只没到条件，整个目录一起留着。审计链是飞检留档，任何保留期都不碰它。
- **连接串是唯一的方言入口**：换 PostgreSQL 只改 `DATABASE_URL`（外加装一次驱动），连接串解析、事务与行工厂的方言差异都收在 `store/dsn.py` 与 `store/db.py` 里，仓储层零方言分支（有源码断言钉住）。**连接串指向 PostgreSQL 时绝不静默退回 SQLite**——那会让服务在错误的库上安静地写数据，比启动失败难查得多；密码只从环境变量来，连接串的摘要与 repr 都不带明文。
- **`/docs` 说的就是服务真实返回的**：错误码表与各接口 `responses` 同源，422 的 detail 恒为 `error_code / message / issues[{code, field, reason, suggestion}]`——不是框架默认的 `[{loc, msg}]`。挂接方照 `/docs` 写分支，线上 422 一条也匹配得上；同一状态码挂着多个错误码时按码归并在同一条响应里逐个点名，不让后写的顶掉先写的。新增错误码忘了登记到接口上，契约测试会红。
- **滴速只从两处来，对不上就不给时点**：输注医嘱文本（`5ml/h`、`20滴/分`、`15滴/ml` 的滴系数换算）与泵速遥测（MQTT）。医嘱认不出才退到遥测；两个都有但相对偏差超 20% 就判 `rate_conflict`——**不取中间值、不偏向任何一头**，`eta_minutes` 与 `rate_ml_per_h` 都不出现，冲突证据（两个值 + 偏差）随响应与库行留档，该袋这一轮不点名。医嘱按体重给（`5ml/kg/h`）或推注一律判「认不出」，不猜体重也不猜速率。
- **拍坏与查不出数是两回事**：拍摄质检**只降级标记，从不拒收**——曲线、毫升数、ETA 一律照给，
  被拒的只有帧数 / 分辨率 / 帧序这些硬指标（那是 `ingest.validate` 的权限）。反过来，
  无标定、无滴速、无观测也照样 `201`，只是对应字段整体不出现。两条门禁互不吞并：
  一段短片不会因为「拍糊了」就查不出余量，也不会因为「查得出余量」就假装拍得好。
- **判不出来就说判不出来**：倾角、底部窄带这类要靠掩膜形状的量，有效列数不足或没量到掩膜时给
  `null`，不编一个数字出来；文案模板里出现证据里没有的键也宁可留原样。六类问题里只有
  `empty_drip_chamber` 是 info 级（已知量偏差，不是护士的错），它不标 `degraded`、不占提示条。
- **轨迹 ID 跨帧恒定、关联只做关联**：一条轨迹一个 ID，落空的帧留 `null` 占位（序列长度恒等于帧数），终止后不复活也不凭空新建。打分刻意偏向几何（质心 + **袋底纵坐标**）、几何不过则 IoU 一票否决——液面下降会让 IoU 天然衰减，两袋贴住时 IoU 会对两条轨迹同时接近 1.0，只有几何能分出谁是谁。一袋被管路阴影切成两块、两个候选得分接近时**不猜**，本帧留空等下一帧或交人工认领；跨帧面积比抖动超阈值则降置信并打 `inconsistent` 留档，但**保留原值**，不抹平也不丢帧。关联层不做分割：它只吃已分好的掩膜，推理入口仍只有逐帧传播那一条。
- **原始值永不篡改，异常只降级**：平滑这一层**只加不改**——原始序列原样返回，
  物理上不可能的上升段标 `outlier` 并保留原值（抹平了就没人知道这一帧拍坏了），
  被挡住的帧保持 `null`（缺一帧就是没测到，不是「沿用上一帧」）。受限重建是**单独一条
  序列**，只在端点齐全且缺帧 2–10 帧时补，补哪些帧、为什么补都逐条留在 `smoothing.gaps`。
  换液后的新液面不会和旧袋的读数加权，反常块之后一阶平滑重新起算。
- **遮挡不丢弃、不猜接**：被挡的帧保留位置、面积比留 `null` 不插值；恢复时拿库里最近几条记忆**按相似度加权**一起比对（不是只比最新一帧——最新那帧可能正被挡着），对不上就继续记遮挡，超过丢失窗口置 `lost` 并交出轨迹，**绝不静默新建轨迹把两袋曲线接在一起**。
- **记忆定长、会衰减、脏记忆进不来**：每条轨迹只留固定条数（默认 4）的记忆，帧数翻多少倍都不涨；权重随帧数衰减，衰减到门限以下就**没有依据**（上层不猜，而不是拿快过期的记忆硬接）。被压住一半的帧几何失真、只更新位置**不参与身份判断**（否则遮一结束、恢复正常的那帧反倒会被判成「拍到别的」）。与记忆矛盾的观测**拒收**：不进库、不出面积比，拒收次数留档可查。库由遮挡跟踪器**单一持有**，下一帧提示仍只由传播层那一处产出——没有第二套推理入口、没有第二份状态。
- **跨轮重锚不猜、不接错**：同一输液架下一轮巡视按「挂点几何 + 颜色 + 液位 + 标签区」四项加权判定是不是同一袋；最高分不够、与次高分分差太小、袋序对不上、外观看不清，或**液柱比上一轮还高**，一律标 `unbound` 交护士在候选列表里认领——**绝不默认取置信度最高的那只**。已确认换掉的袋不再被接上。
- **交出之后靠三条证据接回，接不上就一直是「找不到了」**：再获取只在丢失位置附近的一块区域里重扫（一次枚举服务多条丢失轨迹，区域面积有上限），每条候选要同时过「与最后可见那帧的几何吻合」「落在本袋位的挂点竖列」「颜色不像换过的」三关，总分还要与次优拉开距离才接回。**缺一条证据不算 0 分，而是把剩下几条的权重重新归一**——否则「槽位序号未知」会把每条轨迹的白白扣掉四分之一，证据齐备也接不回来。接回的是**同一条轨迹的原曲线**，不新建、不重算前面的段。
- **审计链只追加**：认领、改绑、重锚判定、点名产出、护士确认，以及**被拒绝的非法迁移**，都往 `audit_log` 追加一行（`accepted` / `rejected` 都记），只追加不修改不删除。
- **业务写与审计写同生共死**：状态推进与对应审计行在**同一个事务**里——审计写失败（磁盘满、库被锁、行超长）会把业务写一起回滚，点名/确认宁可整体失败重做，也不留一个查无实据的 `needs_change`。故障注入用的是 `audit_log` 上的数据库触发器，不在产品代码里留任何只为测试存在的开关。
- **append-only 是可验证的，不只是一句纪律**：审计包带一条滚动链摘要（按行序逐行 sha256，取前 32 位）。改动任何一行、或**删掉中间一行**，摘要都会变——留档人拿 CSV 重算一遍，对不上就说明这段审计被动过。
- **导审计包只读、且不硬套归属**：导出一个字都不写回（查这一次本身不留痕）；导出维度用飞检的问法（按架 / 按床 / 时间窗 / 七类动作），而不是内部动作码。**袋型标定是病区级记录**，不按架/床归属，因此按架导出时不出现——一个 `TYPE-A` 版本对全病区每一架都生效，硬安一个架号等于替它编一个不存在的归属。
- **多袋并行只有一条推理路径、连接键只允许是袋次 id**：一架 ≤6 袋共用一次上传、一次传播（不是逐袋各跑一遍——那会让算力随袋数线性膨胀，同帧各袋也失去可比性）；每帧的掩膜按 `bag_seq` 归位，起锚后身份集合**冻结**，中途塞新 id 直接报错——多出来的袋子只能走再获取或护士认领。**面积退化按袋不按架**：某袋估不出袋腔只让它自己不出读数，不得把同一架其余袋子的余量一起变成假数。槽位分配三通道（挂点竖列 / 质心垂向漂移 / 面积量级）任一硬门限不过即淘汰，面积偏离同架中位数超过一倍直接判并袋/杂物；**一个挂点最多接一条轨迹**，争议不默认取最高分。
- **不可信数字不出门**：无标定或低置信时，响应中不出现毫升字段（字段整体不出现，不返回 null 占位）。滴速给不出来时**只压住时点、保留毫升**，并把该袋的换液点名标为抑制——不拿猜出来的时点催护士换袋。
- **缺证据不等于「看着不像」**：某一侧的某项判据不存在时（标签区没看清、库里是旧版描述子），那一项**退出加权并重新归一**，而不是记 0 分。0 分意味着「看着确实不像」，缺证据意味着「没看见」——两者混同会系统性低估证据齐备的那一侧，让本来该接上的袋永远接不上。降级方向只有一个：宁可少用一项判据，也绝不把「没存」当成「没有标签」。认准时也不给历史会话指针之外的东西：`descriptor_mode` 与 `reanchor_driver` 如实随响应与审计落库，事后复盘「当时为什么没接上」看得到是哪一项。
- **贴住的两袋不合并**：粘连判定取在形态学闭运算**之前**的阈值图上（缝隙一旦被桥平，它和「一个特别宽的袋」在几何上无法区分），切割落在闭运算**之后**（否则刚切开又被桥回去），缝上 2 px 两边都不给。缝隙窄到 ≈2 px 时它在阈值那一步就已不存在，只能合成一块——这种情况会标出来，不假装分得开。
- **标定只有一条生效版本**：同袋型永远只有一个生效版本；改版不覆盖旧记录，历史会话按新版本重算并留 append-only 轨迹（改前那一格留空，不填 0 冒充）。
- **未确认不出站**：出站前先查会话状态，不是护士确认过的 `replaced` 一律拒发（连 HTTP 请求都不发），事件行留在库里等确认——系统不替护士签字换袋。点名清单这一层**只读**（响应里 `writeback_queued_count` 恒为 0），查一次清单不可能把一条未确认的换液推给对端。
- **写回不丢、可重放**：出站失败按失败类别分流（4xx 业务拒绝不重试，5xx 与超时指数退避 ≤2 次），耗尽后事件置 `pending_writeback` 并写审计；每次退避重试各留一行，失败摘要过脱敏，凭据不进库、不进日志。**欠账落盘**：这笔事件进 `writeback_queue` 台账（载荷快照、累计尝试次数、下次可重试时刻、错误摘要），进程重启也不丢——待写回清单里看得见，信息科可人工重放；重放只投已存在的事件，不产生第二条换液记录，已送达的重放一次 HTTP 都不发。
- **失败分类只有一张表，退避名单是它的投影**：11 类失败（业务拒绝 / 对端 5xx / 3xx 与未知码 / 协议不成立 / 建连超时 / 连接池 / 连接被拒 / 读超时 / 写超时 / **半开连接**）各自写死了「可重试 / 终态 / 对端是否可能已收下」，退避名单、错误摘要与 [`docs/nurse-exec-contract.md`](nurse-exec-contract.md) 的失败分类表都由它生成——加一种失败不会出现「分类说不可重试、退避却照发」的矛盾处置。**标「对端可能已收下」的三类**（读超时、写超时、半开连接）既值得重试又不能保证重发不会变成两条，幂等键就是为它们准备的。
- **续传只有一条主干，断点只前进**：分片提交把已收齐的帧按帧序拼好后交给 `process_track_upload`——与一次性 `/tracks` 是同一个函数，分片不是「简化版主路径」。重复帧**先到先得**，且先按字节核对是不是同一帧：重发同一片安静去重（断点不回退、不膨胀），内容不同则当场问清楚——逐帧液面变化在整幅画面上只占千分之几的像素，像素级近似根本分不开「重试」与「按片重编号」，误当重复丢掉就会让断点永远停在原地且**没有任何报错**。
- **重放留档、清理不越界**：整段重传先把被盖掉的那一版快照进 append-only 的版本历史（与覆盖同事务，审计同进同出），所以「上一版是多少毫升」永远查得到；重放**不重置业务状态**（已确认换袋的终态不会被一次重传撤回），幂等键由 (会话, 袋序) 决定，重放也发不出第二条事件。半成品清理只遍历 `_staging/` 下「开着没提交且已过保留期」的行，正式帧目录连看都不看——不存在「清理半成品顺手删掉已算好的余量曲线」。
- **只落必要标识**：仅落床号、袋序、数量与派生量，不落患者姓名等可识别明细。
- **入站是双通道、同一份真相**：MQTT 与 webhook **共用同一个** `TelemetryChannel`——同一份
  解析、同一套去重表、同一个缓存。这不是省事：切通道的灰度期里同一条遥测从两条路各进来
  一次是常态，两个各写一套的解析器必然在某次固件差异上给出不同结论，而「两条遥测不一致」
  比「没收到遥测」难查得多。去重键是 `(device_sn, ts)`；泵固件不发 `ts` 时退化为
  `(设备|架:袋, 载荷摘要)`——内容完全一致的两条消息对 ETA 没有增量信息，按重复处理是
  安全的，两个计数都摆在运行摘要里。**为什么不能只靠缓存比较**：缓存按 `(架, 袋)` 比，
  只能挡住同一袋的重投；重连后 broker 重投的是上一次会话里的各袋消息，那时很可能已经
  换了输液架，那批消息在缓存里是空的，每一条都会被当成新读数吃进去。
- **异线程不碰主库连接**：主 SQLite 连接建在事件循环线程上，而 broker 回调与退避重连
  线程都在自己的线程上。直接写会抛线程亲和性异常，而**这个异常是从 paho 的网络循环
  线程里抛出去的——线程就此死掉，遥测从此静默消失，连一行审计都留不下**，比不写还难查。
  所以异线程的审计只入队（上限 512 条，满了丢最老并计数），由事件循环线程在探活与摘要
  请求时落库；队列深度与丢弃数都摆在运行摘要的 `pending_audit` 里，不静默。
- **webhook 先验签再解析**：签名不过的请求连 JSON 都不解（未验签的载荷一旦开始解析，
  已经在替攻击者消耗 CPU）。比对用常数时间比较，签名头是可以被反复试探的公开输入。
  时间戳**在签名串里**（`ts.body`）——否则攻击者把时间戳头一换，签名照样成立，重放窗口
  形同虚设。不带时间戳的请求只对请求体验签放行（院内有些网关确实不会加这个头），此时
  **没有重放保护**，这一点在响应的 `timestamp_enforced` 与对接文档里都写明，不让部署方
  误以为有。没配签名密钥就没有这个端点（404），而不是配一个默认密钥开着它。
